# Paid landing click references

The inline `scripts/paid_click_reference.js` recognizes only the five reviewed Google destinations and three reviewed LinkedIn destinations (Austin, Boston and NYC LL84). LinkedIn uses `li_campaign=l4/l5/l3`, `li_arm=A/B` and a valid UUID `li_fat_id`. It writes `ustaL1_<campaign>_<arm>_<base36 landing second>_<UUID>` only to that product's existing Stripe payment-link anchor. Google references retain their `usta1_` format. Nothing is stored in a cookie or browser storage. Conflicting channel IDs, invalid codes, another product's link, existing unrelated references, GPC, DNT and explicit advertising-consent denial prevent decoration. Consent revocation removes our references before click.

A reference is attribution context, never evidence of payment. The paid-media collector must read a live paid Stripe event, match the product, count actual net cash and deduplicate the payment intent. Browser tests do not submit conversion events. LinkedIn Conversions API permission was refused on 2026-09-07; this change does not make reporting or paid acquisition proven. It does not cover blog-sponsorship or platform API checkout flows. No campaign is enabled here.
