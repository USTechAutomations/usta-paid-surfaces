The three worth reading twice

roguefitness.com is the only file that came down. A checkout manifest was there on 28 and 29 July and gone on 30 July. It has answered not-found on every one of the 20 days we have read it since, so this is a file that was taken down and left down, not a fetch that failed. It is the only disappearance in the whole window and we do not print one until it has stayed gone.

on-running.com’s server never once said not-found. It answered 200 for /llms.txt on every day we could read it, and on the first 43 of those days it sent a web page rather than the file. The real file appeared on 28 Jul 2026. dillards.com did the same thing for two days: not-found for weeks, then 200 with a web page on 28 and 29 July, then the real file on 30 Jul 2026. Anything that only reads the status code would have called on-running.com’s file present since June. Only the saved body tells you which day the real one arrived.

bowflex.com and chubbiesshorts.com sit either side of a hole in our own reading. We have no read at all for 18, 19 and 20 August, so all we can honestly say is that those three files went up somewhere between 17 and 21 August. We give you both dates and let you see the gap rather than picking a day.

The size of the panel, and the honest count

We ask 276 companies for the same seven files every day and have kept every answer since 11 Jun 2026. That is 66 sealed days and 127,512 saved reads, with exactly 1,932 reads on every one of those days and no half-finished day in the set. On our newest read, 22 Aug 2026, 202 companies served a real robots.txt, 92 served agent instructions at /llms.txt, and 67 served a checkout manifest at /.well-known/ucp. Not one served an agent card, at either of the two addresses those live at, and not one served either of the two tool-server files, on any of the 66 days.

Counted by company rather than by file: 100 of the 276 served at least one of the six files an automated buyer looks for. 98 served none of them. For 71 of those 98 every one of the six came back a plain not-found. The other 27 answered 200 at least once with something that was not the file — still not the file, but not a not-found either, and we say which it was rather than rounding it up. The remaining 78 we could not fully read, and 63 of those gave us nothing readable on any of the six. Those three groups are kept apart on every page in this feed, and each one is named and broken down on what this feed covers.

155 answers of 200 on our newest read were not the file. They came from 39 companies whose servers hand back a web page instead of a not-found. Six of those companies did it for all seven addresses we asked for; 13 did it for only one. Across the whole window that has happened 10,048 times. We never count a status code as a file: we keep the body and check that it really is that kind of file. Anything whose first character is a tag is a web page, not a document, and one company’s server even prefixes its file with an invisible marker before the tag.

Seven days in the window have no read at all — 19 Jun, 4 Jul, 15 Jul, 8 Aug, and 18, 19 and 20 Aug 2026. A file that went up and came down inside one of those gaps is a change we never saw. We show the gap instead of filling it in.

The panel is a fixed list of 276 companies, chosen before we started reading. It is not the web and it is not a ranking. A company that is not on the list is not on any page in this feed, and we will tell you that in the first email rather than sell you a name we do not read.

Doing this yourself

You can fetch any of these seven files from any company yourself in a second. What you cannot fetch is yesterday’s. None of these files is versioned, dated, announced or archived, so the day one appeared is not recoverable from the company — it only exists if somebody was already asking every day before it happened.

The other half of the work is telling a real file from a server that says 200 and means nothing. That is why the honest count above is smaller than the number of 200s, and it is the part that quietly breaks anything built on status codes alone.

What this page cannot tell you

An agent-instructions file is not a checkout. It tells an assistant what to say about a company. A company can serve one and still have no way for a robot to buy anything, and this feed will not tell you those are the same thing.

A server answering 200 is not proof of a file. We count a file as there only when the body we saved really is that kind of file. Answers of 200 that hand back a home page or an error page are thrown out of the count, and the tables say which they were rather than rounding them up.

The panel is a fixed list of 276 company websites. It was frozen before collection started. A company that is not on that list is not missing from this feed — we have never asked it anything. Send us the names you care about and we will tell you which of them are in the panel before you spend anything.

We compare the bytes of a file, not its meaning. A company that stamps today’s date inside its file looks like it changes it every day. The tables say so rather than selling you that churn as news.
