What you get

  • One file a week24 instances: 1 machine x 6 jobs, 1 machine x 8 jobs, 1 machine x 10 jobs, 1 machine x 12 jobs and on up to 3 machines x 12 jobs, in each of the four rule families.
  • Eleven columnsInstance id, pack date, rule family, machines, jobs, naive minutes, best-found minutes, minutes saved, saved %, the busiest machine's minutes (how long the most-loaded machine runs, so you can see the bottleneck), and the sequence to run per machine. The free sample carries the first ten; the sequence column is the one you pay for.
  • The matrix behind every rowA JSON twin of the file carries each instance's job labels, the full changeover-minutes matrix, the naive order and the best order, so you can re-check the arithmetic.
  • The free sample is this week's file without the sequence columnEvery shape and every saving is public. The order to run is what you pay for.

Limits, plainly. The instances are generated, not measured. The shapes are bounded: at most 3 machines and 12 jobs. The minutes are synthetic. Best found is not proven optimal. Nothing is built for your factory: you match a shape and take its order as a starting point, then check it on your own minutes. If your shop has more machines, more jobs, or changeover times that depend on more than the job before, this file does not fit.
